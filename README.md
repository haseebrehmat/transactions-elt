# Banking Transactions ETL Pipeline

This project implements a distributed ETL pipeline using **PySpark**, **Apache Iceberg**, and **MinIO (S3)**, orchestrated by **Apache Airflow**.

## **Tech Stack**
- **Orchestration:** Apache Airflow
- **Compute:** PySpark (Spark 3.5.0)
- **Table Format:** Apache Iceberg
- **Storage:** MinIO (S3-compatible)
- **Database:** Postgres (Airflow Metadata)

## **Pipeline Stages**
1. **fetch_raw**: Generates random banking transaction data and uploads it to MinIO.
2. **load_clean**: Ingests raw CSVs into an Iceberg `raw_transactions` table.
3. **normalize**: Converts types (Decimal, Timestamp) and standardizes text.
4. **filter_success**: Removes failed/cancelled transactions.
5. **enrich**: Adds derived fields like `is_high_value` (> 10,000) and `txn_day`.
6. **aggregate**: Generates a daily summary of transactions and amounts per customer.

## **How to Run**

### **1. Infrastructure Setup**
Ensure you have Docker and Docker Compose installed.

```bash
docker-compose up -d
```

### **2. Accessing UI**
- **Airflow:** [http://localhost:8081](http://localhost:8081) (Admin/admin)
- **MinIO:** [http://localhost:9001](http://localhost:9001) (admin/password123)
- **Spark Master:** [http://localhost:8080](http://localhost:8080)

### **3. Setting up Spark Connection in Airflow**
By default, the DAG uses `spark_default`. You must configure it in the Airflow UI (**Admin -> Connections**):
- **Conn ID:** `spark_default`
- **Conn Type:** `Spark`
- **Host:** `spark://spark-master`
- **Port:** `7077`

## **Observability & Result Inspection**

Every time the DAG is triggered, a unique execution folder is created in MinIO under the `pipeline-runs` bucket (e.g., `run_20260103163000`). 

### **1. Stage-wise Snapshots**
Each step of the pipeline saves its intermediate results as a CSV file in the run folder:
- `0_extraction/`: Raw CSV data generated by the fetch task.
- `1_raw_ingestion/`: Initial data loaded into the raw Iceberg table.
- `2_basic_cleansing/`: Data after dropping nulls and trimming.
- `3_parsing_normalization/`: Data with casted types and normalized columns.
- `4_filter_success/`: Only successful transactions.
- `5_feature_enrichment/`: Data with derived fields (`is_high_value`).
- `6_daily_aggregation/`: Final daily metrics.

### **2. Analytics Dashboard (GUI)**
We provide a built-in **Streamlit Dashboard** to visualize all stages of the pipeline without needing any local installations.

- **URL:** [http://localhost:8501](http://localhost:8501)
- **Features:** 
    - Dropdown to select different pipeline runs (based on timestamps).
    - Tabs for each ETL stage (Extraction, Cleaned, Success Only, Enriched, Daily Aggregation).
    - Real-time metrics for the final aggregation (Total Volume, Transaction Counts).
    - Data tables to inspect specific rows in each stage.

### **3. Manual Query (Inside Spark)**
If you want to run custom SQL queries against the underlying Iceberg tables:
```bash
docker exec -it transactions-etl-spark-master-1 spark-sql \
  --conf spark.sql.extensions=org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions \
  --conf spark.sql.catalog.iceberg=org.apache.iceberg.spark.SparkCatalog \
  --conf spark.sql.catalog.iceberg.type=hadoop \
  --conf spark.sql.catalog.iceberg.warehouse=s3a://iceberg-warehouse/ \
  --conf spark.hadoop.fs.s3a.endpoint=http://minio:9000 \
  --conf spark.hadoop.fs.s3a.access.key=admin \
  --conf spark.hadoop.fs.s3a.secret.key=password123 \
  --conf spark.hadoop.fs.s3a.path.style.access=true
```
Then run: `SELECT * FROM iceberg.daily_transaction_summary;`

## **Project Structure**
- `dags/`: Airflow DAG definition.
- `spark_jobs/`: PySpark transformation scripts and data generator.
- `docker/`: Custom Dockerfiles for Spark and Airflow.
- `data/`: Local persistent storage for MinIO and Iceberg.
